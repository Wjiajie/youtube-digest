更新：2026-09-10；固定点 `d48aeff`。P4 本地切片已实现并验证，尚未托管迁移、发布或重载用户安装的扩展。完整状态见[执行路线](execution-roadmap.md)。

## 产品语义

学习、实践、检查点和复盘节点都可以定义预计投入与完成依据，不要求绑定视频，也不限定职业领域。

- 预计投入以分钟表达，未知时明确留空，不默认成 0 或从视频长度推断。它是规划估计，不是实际学习时长，更不是掌握程度。正整数上限来自存储整数范围，不是产品建议的节点时长；合理拆分与每周负担属于后续 Agent 质量检查。
- 完成依据描述可观察的产出或证据，允许暂未填写；未填写会明确提示，不捏造标准。它不等同于成果记录，也不会自动改变节点完成状态。
- 节点信息属于正式路径：修改先成为提案，用户审阅变更前后值后确认，才连同路径写入同一蓝图修订。只改预计投入或完成依据同样是有效变更。明确清空也需确认。
- Goal Brief 的每周时间与整体成功标准仍属于规划前定义，不会因为节点字段增加而自动绑定、确认或生成路径。后续 P6 需要独立的确认修订门禁。

## 顶层设计

复用 TypeScript／Zod 领域模块、Supabase PostgreSQL 与现有提案应用事务；不新增另一套节点写入通道。Web 结构化编辑器使用既有双主题语义控件，Markdown 导出同时携带预计投入与完成依据。

当前格式升级为 Blueprint Snapshot 2，节点显式包含两个字段；空值也具有明确含义。当前写入拒绝旧格式与未知字段，防止旧客户端忽略新字段后覆盖正式信息。历史 Snapshot 1 的提案和修订保持原 JSON；历史读取与当前写入解析分开，只有准备供用户重新审阅的草稿才显式转换格式。

新增 `read_blueprint_snapshot_v2` 保持一次语句快照、调用者权限与精确扩展身份判定；旧读取函数保留为旧格式只读投影，不能用作当前读取失败时的降级。正式表仍不向客户端开放直接写权限。新字段与提案、蓝图版本、修订在同一事务中生效；未知字段、非法值和冲突会回滚整次应用。已应用的旧请求使用原提交 ID 重试仍被识别；未应用的旧提案需重新核对，不自动改写原提案。

## 发布与兼容边界

本批只改本地。后续必须先应用增量，再发布依赖新读取的 Web；保留旧读取避免迁移立即破坏旧页面读取，但迁移后的旧格式写入会被拒绝。需要控制切换窗口，不能把“旧读取还可用”说成旧客户端仍可编辑。

新扩展源码使用共享解析器，可接受新格式；旧安装版可能拒绝 Snapshot 2，因此托管发布前需要完成扩展升级安排或明确的版本协商。不得部署后才宣称双端无影响。回滚旧 Web 不能恢复允许旧格式覆盖的写入函数，也不能删除新字段来适配旧版本。
