## 已实现的行为

服务器为明确配置了保留策略的账号创建资源运行。没有策略时拒绝新检索，不预留次数、不发起提供方请求。测试账号的策略只用于本地夹具，没有配置任何真实用户策略。

一次检索链只有一份可信来源起点与不可延长的内容期限。后续字幕读取、匹配和采用核验继承原期限；更新核验时间、重复读取、修改账号策略都不能给旧材料延期。执行的 120 秒租约和采用的 10 分钟确认窗口仍是不同概念。

到期后：

- RPC 读取、执行权申请、完成及采用确认停止使用旧正文，直接 Data API 读取也不能绕过限制。
- 清理覆盖同次检索的所有字幕／匹配副本和采用核验正文，拒绝未确认提案；保留最小终态回执与原运行 ID。
- 排队但未执行的次数只退回一次；已经取得执行权的不退款。迟到完成仍校验原执行权，不能复活正文或再生成提案。
- 正式蓝图、已确认修订、绑定、学习会话、笔记、成果和自评保持不变；精确重试已确认提案仍返回原修订。
- Web 到期时隐藏材料和后续操作，恢复标签页也检查期限。不会自动刷新、重新核验或再次消费；用户主动读取后看到“资源证据已到期清除”。

调用提供方前及在途取消已加入期限信号，但目前依赖 Node 与数据库绝对时钟一致：后续测试已证明偏差时仍可能发起过期请求，因此这部分尚未验收通过。数据库到期拒绝／清理是另一层保护，不弥补已发出的请求，也不保证提供方停止计费或删除副本。

旧版记录没有可信期限：升级保留原行，不推测授权、不回填日期、不在迁移中删除正文；RLS 和 RPC 停止暴露这些旧正文。持有原运行链接的用户仍能明确清除整条链，页面不需要先加载旧材料。已清理的历史回执继续可读。

## 顶层设计

沿用[主动清除](resource-evidence-clearing.md)的终态模型，用共享整链清理核心处理手动与自动原因。新元数据与业务回执分离，客户端不能提交或修改期限。采用前的来源检查独立验证期限，不把“结果曾经成功”当作“现在仍可使用”。

清理与 begin／claim／finish／apply 保持同一蓝图锁顺序。读取失败的事务可能回滚其中的惰性清理，因此不能把拒绝响应当作数据库已完成擦除的证明。硬期限访问限制与独立维护扫描必须同时存在。

私有维护入口按账号限批、跳过已锁住的蓝图，只返回处理账号数，不输出正文。账号策略只有数据库维护者可设置，Web、扩展与 worker 均不能读写。策略上限 25 日是工程保护上限，不是任何内容的授权期限；获许可后仍须按实际权利范围配置更严格的窗口。

浏览器展示保护不是 DRM 或全局撤回：已下载的响应、页面内存、离线副本及被修改的客户端时钟不能靠本地定时器可靠擦除。服务器仍是访问与执行的安全边界。

### 重复验证发现的时钟缺口

最终完整真实 Auth 回归 63 项中 **61 通过、2 失败**：延迟 claim 回执后仍调用检索／详情／字幕；在途搜索也可能返回成功正文而非到期回执。缩小到这两项后再次复现，不是只在全套测试中出现。

失败时观测：数据库来源时间 `20:14:12.077746Z`、期限 `20:14:13.077746Z`，Node 接收回执时却为 `20:14:10.049Z`，延迟后为 `20:14:11.251Z`。另一次同范围测试的数据库和 Node 时间接近，两项通过。一次独立即时 DB/主机快照也接近；尚未确定偏差来自虚拟机、测试进程还是时钟调整，不能写成已定位基础设施根因。

现有按 `Date.now()` 比较数据库绝对期限的实现不足以证明跨时钟安全。后续需在真实编排边界验证可信数据库观测时间与本地单调耗时的预算设计，覆盖正负偏差、回执延迟、在途请求、主动取消和迟到完成；这只是下一步设计方向，尚未实现。不能通过延长测试 TTL、删除失败用例或单纯重跑关闭问题。
