# 学习位置的云端保存与恢复

2026-09-11 · P4/P8 本地增量 · 固定点 `93a012a`。

本文保留云端基础批次的范围与验证记录，不表示已经托管上线。后续双主题界面、扩展主动取时、恢复草稿和明确跳转已在本地接通，最新状态见[双端继续学习工作台](position-workspace.md)。不自动监听播放器、不增加浏览器权限，也不把笔记时间戳当作最近观看位置。

## 位置不等于进度

已登录的 Web 与配置认可的扩展可以明确保存节点下某个 YouTube 资源的位置，另一客户端读取同一份云端记录。零秒有效，用户回看时可以保存更早的位置；不要求位置单调增加，不推算观看比例、观看时长、节点完成或掌握。

本批位置是客户端明确提供的整数秒，不证明实际视频时长或观看行为。不会创建学习会话、笔记、成果、自评或蓝图修订，也不会调用 YouTube、字幕或模型提供方。

## 可靠保存与历史归属

路径版本与位置版本各司其职：前者确认当前节点和资源，后者防止旧设备覆盖另一设备较新的保存。同一资源从位置版本 0 开始，每次成功保存加一；不同提交基于同一位置版本并发到达时，只能有一个成功。冲突要求重新读取并明确决定，不自动覆盖。

同一提交标识与完全相同命令返回原回执，即使后来改名、移除资源或归档节点。旧回执重试不会提升为最新位置；改了位置、版本或来源却复用原标识会被拒绝。UUID 大小写不改变身份。

服务器冻结保存时的目标、阶段、节点与视频来源，不接受客户端伪造这些字段。原地编辑资源仍可能保留相同绑定 ID，因此将来展示“继续学习”时，必须比较保存的节点／视频与当前来源，不能只用绑定 ID 认定位置仍适用于当前视频。新资源使用新位置序列；原地修改绑定则保留同一序列，但新一次明确保存才记录新视频来源。已有回执不重写。

记录与正式路径确认共用蓝图锁，避免读取混合来源。写入采用不可变回执；读取返回同一快照下的正式蓝图及每个绑定的最新位置，按保存时间与 ID 倒序取最近 50 个绑定。也可以明确指定一个绑定读取最新位置，避免第 51 个及更早的资源无法取得保存所需的版本。旧版本保留用于精确恢复，这不是完整历史分页、导出或自动清理策略。

## 共享实现与权限

- [领域模块](../packages/domain/src/learning-positions.ts)：严格命令、明确位置版本、规范 YouTube 来源与完整工作区读取校验。
- [服务端用例](../apps/web/src/lib/learning-positions.ts)：核对身份、冻结上下文和回执一致性；不确定结果不宣称成功。
- [Web Actions](../apps/web/src/app/learning-position-actions.ts)：每次验证当前身份与页面绑定账号。
- [HTTP 入口](../apps/web/src/app/api/v1/learning-positions/route.ts)：写入只允许已核实的配置扩展身份，Cookie-only 写入被拒绝；私密读写禁止缓存，正文有实际字节上限与五秒读取期限。
- [增量迁移](../supabase/migrations/20260910171517_learning_positions.sql)：位置回执、逐绑定版本与受限函数入口；原有账号不回填虚构位置。

数据库启用账号 RLS，显式授予读取／函数执行权；匿名、匿名登录、未知 OAuth 客户端及跨账号访问被拒绝，不允许用户直接改表。公开调用者权限函数转交固定空 search path 的窄职责私有写入函数。新增表不依赖隐式默认授权，符合当前 [Supabase 显式授权要求](https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically)。应用不使用管理员密钥。

## 验证与发布边界

命令校验与公共读写入口先写失败测试再实现；重复视频参数的非规范 URL 另有失败回归。真实本地 Auth 检查双客户端读取、并发版本冲突、原请求恢复、原地编辑、替换／归档、双账号与 UUID 大小写。生产 HTTP 检查真实 Next 服务的读写与未结束上传；先复现代理等待 EOF，随后只将本入口交由自身认证和有期限的正文读取器处理。

验证命令：`npm run test:agent-runs`、`npm run check:m1`、`supabase test db`、`npx playwright test --config playwright.notes.config.ts`。生产 HTTP 使用仅回环地址的外部 Auth／PostgREST 夹具，真实数据库另由本地 Auth 集成验证；不将这两者冒充真实扩展 OAuth 或播放器验收。

本批验证通过：908 项应用测试、79 项 Edge 测试、四工作区类型检查、6 项压缩／安装回归、升级契约、向导及 Next／WXT 构建；60 项真实本地账号集成（新增 7 项）、954 项数据库检查（新增 76 项）、4 项生产 HTTP（笔记与位置各两项）及 48 项默认 Web 回归。第 51 个资源的定向读取／继续保存已用真实 Auth 和数据库验证。新增集成文件严格类型检查通过，位置夹具账号已全部退出并删除；没有新增 UI，不声称通过继续学习界面或播放器验收。

升级前后逐行核对已有数据，旧账号不制造位置记录；本地 18 项迁移对齐，public/private 结构差异为空，安全与性能顾问无告警。数据库 lint 仍保留既有五组函数警告，不表述为全库零风险。
