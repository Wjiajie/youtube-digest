# 云端账号偏好：数据、Web 与扩展切片

2026-09-10。本文记录账号主题切片的源码、本地验证与托管验收；正式人物、完整主题旅程和其他阶段仍以[执行路线](execution-roadmap.md)为准。

## 顶层设计

主题选择属于账号表现偏好，不属于 Blueprint Snapshot、Proposal 或 Revision。当前复用每个 Auth 用户已有的 `profiles`，不创建第二套账号，也不重置或迁移历史蓝图。

- 保存主题 ID、主题契约版本，以及独立的偏好修订号。Web 修改；已授权扩展读取同一条记录。
- 修订号由数据库维护，保存时带上读到的版本；旧标签页的更新会返回冲突，不静默覆盖新选择。同一主题的重复保存不增加修订。
- 蓝图版本、节点、学习记录均不因主题变化而修改。展示名称仍可更新，但不增加主题修订。
- 存储可保留未来主题的合法 ID／版本；当前 Web 仅允许保存已打包的注册主题。较旧渲染端可以选择本地回退，但不能在读取时覆盖账号原有选择。
- 不接受主题资源 URL，不让账号偏好成为加载任意远程资源的入口。

## 已实现

增量迁移扩展 `profiles`，复用已有 owner SELECT 与 Web-only UPDATE RLS。进一步收窄列级 UPDATE：客户端只可编辑展示名称和主题，不能伪造修订号、账号归属或时间戳。触发器位于私有 schema，以调用者权限执行，并撤销客户端直接执行权限。

服务端使用 Next.js Server Action 保存主题，通过现有 Supabase 身份验证与同账号条件更新；只读 Route Handler 向 Web／固定 OAuth 扩展提供偏好，并设置 `private, no-store`。错误结果区分未登录、无效选择、版本冲突和服务不可用，不返回数据库详情。没有新增管理员密钥、付费服务、遥测正文或实时订阅。

主要入口：

- `packages/domain/src/account-preferences.ts`：独立于蓝图快照的数据契约。
- `apps/web/src/lib/account-preferences.ts`：读取、受支持主题校验、条件保存与返回值校验。
- `apps/web/src/app/account-preferences-actions.ts`：Web 保存入口。
- `apps/web/src/app/api/v1/account-preferences/route.ts`：已验证身份的只读入口。
- `supabase/migrations/20260909153706_account_theme_preferences.sql`：可审阅增量迁移。

## 2026-09-10：真实页面与扩展接入

Web 主页、扩展连接设置及已登录授权页已接入账号主题容器。选择先形成当前页面的外观预览，只有明确保存且服务端成功后才显示已保存。主题切换不以主题 ID 重建业务子树，蓝图草稿、文字选区与焦点保留；窗口重新聚焦或恢复可见时重新读取云端偏好。无本页修改时跟随账号，有本页修改且云端修订变化时提示冲突，用户读取后再重新选择，不覆盖蓝图草稿。

Server Action 绑定渲染页面时的账号，并再次验证当前身份；旧页面遇到账号变化不能替新账号保存主题。客户端收到身份变化后隐藏原业务内容，要求重新加载账号，原蓝图的本地草稿不转移给新账号。

扩展只读账号偏好，使用相同主题的紧凑密度。偏好与蓝图并行读取，主题失败不会单独阻断蓝图加载；离线时只使用当前账号的已验证缓存，并明确显示缓存／暂不可用状态。聚焦时仅刷新偏好，不重置当前视频、节点或学习成功提示。账号改变、断开或失效后清理原账号缓存，过期响应不能恢复旧账号内容。

新增并行读取也要求 Auth 正确处理竞争：同一刷新令牌共享刷新请求，会话写入／移除串行执行，授权世代使断开后的旧响应立即失效。回归测试实际延迟浏览器存储写入，确认断开不会被旧刷新恢复；随后连接另一账号仍可用，且读不到原账号主题缓存。

本批主要新增入口为 `account-theme.tsx`、`account-theme-shell.tsx`，以及扩展后台 `LOAD_PREFERENCES`。React 测试使用真实编辑器／扩展 App；扩展运行时测试只在浏览器存储、OAuth 与 HTTP 等平台边界控制响应，没有替换偏好业务模块。

验证证据：

- 生产构建的桌面／移动 Chromium 共 16 项 E2E 通过，覆盖登录失败恢复、匿名偏好拒绝与内部设计页不可公开访问；邮件请求为受控响应，不消耗托管邮件额度。

- ego-browser 任务空间 2 使用真实本地 Supabase 邀请登录与 Mailpit 链接完成回调，未注入会话。选择东方主题并保存后，数据库偏好修订为 1，蓝图仍为版本 0；进入设置、返回主页及整页重新加载后，主题与未提交草稿均保留。

### 提交后复核与竞争修复

双端接入提交为 `16a52dc`。独立规范／需求复核发现两项竞争：主题请求过期会丢弃仍有效的视频上下文，断开期间的延迟蓝图缓存写入会恢复已清理内容。两者均已通过失败测试复现；现在偏好过期只回退到同账号有效缓存，业务上下文仍正常交付；蓝图缓存写入串行化，身份变化后的旧写入完成清理后，新会话才写入，避免误删新缓存。覆盖同账号／另一账号重连及旧写入等待期间新缓存保存，不引入新的后台消息接口。

### 保留的安全与验收缺口

托管 Security Advisor 有两项现有警告，不能引用本地检查来声称托管零警告：

- [authenticated 可执行 SECURITY DEFINER 函数](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)：对应原有 `apply_blueprint_proposal`，是正式蓝图的受控写入入口。复核确认空 search_path、账号归属、版本锁、扩展限制与匿名 EXECUTE 撤销；直接改成 INVOKER 会破坏现有写入路径。但发现此前未覆盖的缺口：缺失扩展配置时未拒绝扩展、缺失 snapshot.id 时 SQL NULL 比较不能可靠拒绝。下一批先补直接 RPC 权限／无效输入失败测试，再以独立增量迁移收敛，不把主题发布当作这些问题已解决。
- [密码泄露保护未启用](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)：当前应用只提供邀请 Magic Link，不提供密码注册／登录界面；此轮没有升级计划或更改密码策略，警告仍保留。

真实第二账号登录隔离、退出后重新登录、托管提供方失败与扩展断网恢复的完整回归仍未完成。本轮验证的是单个既有真实账号的主题往返同步，不等于完整 M1/P1、跨物理设备或 YouTube 视频内的全部学习旅程验收。
