# 规划草案的提案确认

固定点 `0e80e6e`。本批补齐已保存规划 → 准备提案 → 用户明确确认 → 正式路径；不接付费模型，不用浏览器提交的草案替换云端运行。

## 不变条件

- 每次运行最多关联一个提案。准备只读取当前账号的完整 ready 结果，原子核对已确认 Goal Brief 修订及蓝图版本；不修改正式路径。重复准备返回同一个提案，响应丢失不重复创建。
- 关联的提案正文、来源与身份不可通过客户端表更新被替换或解除。普通手动编辑提案继续使用原有流程，不能借旧确认入口绕过规划来源检查。
- 用户再次明确确认才应用提案。确认在同一数据库事务内锁住蓝图并验证 Goal Brief 与蓝图来源，目标定义或蓝图变化后拒绝应用。所有确认路径使用一致的 Blueprint-first 锁顺序。
- 已成功确认的精确请求重试恢复原确认事实，不因之后目标定义修改而误报原操作失败；改换预期版本或确认标识不能伪装成原请求。已应用版本从正式修订读取，不把后续版本当作该次版本。
- 用户可拒绝待定提案；拒绝可重试，不撤销已应用路径。同一运行被拒绝后不自动再建提案或调用模型。
- Web 当前账号可读／准备／拒绝／确认，扩展、匿名及其他账号均不能操作。关联记录只由数据库事务维护，客户端不能自报来源有效。

## 用户界面

延续双主题规划阅读页：新增建议、周预算、假设与原有目标保留情况先展示；用户点击“准备确认提案”后，再选择“确认并应用”或“拒绝这份提案”。状态刷新不会创建或应用提案。跨设备重新打开可恢复待确认／已确认／已拒绝状态。

未知网络结果保留可核对入口；身份失效隐藏私人内容，确认时再次匹配账号／运行／提案。成功提供正式路径入口；过期来源明确要求返回定义，不允许无提示重新基于新版本应用。确认只改变正式蓝图，不将计划节点视为完成或掌握。

## 验证与边界

公开 RPC 与用户页面为测试 seam：真实本地 Auth／PostgreSQL 验证幂等、来源并发、旧确认入口、直接改表、拒绝和用户隔离；生产浏览器验证两步确认及重开恢复。保留原有手动提案回归、现有账号迁移和扩展安全检查。只做增量迁移，不改历史迁移、不重置数据、不发布到托管。

真实模型生成入口、费用账务、Skill 澄清／资源编排及真实质量评测仍按总路线继续。此批成功不等于完整 P6 或商用双主题验收完成。
