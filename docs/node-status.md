# 节点状态确认

更新：2026-09-10；固定点 `2596ab9`。本地切片已实现并验证，未部署。完整阶段状态以[执行路线](execution-roadmap.md)为准。

## 产品契约

用户为正式路径节点明确选择“尚未开始／进行中／自我确认完成”，完成时回显当前完成依据，也允许重新打开；没有记录时显示尚未开始，但不伪造确认历史。四种节点均有效，不要求视频或成果。没有成果、没有完成依据仍允许自我确认，界面必须明确指出缺口；关联成果也不代表系统认证掌握。

状态与规划分开：操作不改 Blueprint Snapshot、正式路径版本或已有成果。每次确认留下不可覆盖的历史，保存当时的路径名称、蓝图版本、预计投入和完成依据。路径后来更改，旧确认仍按原上下文解释；当前完成依据与确认时不同须提示重新核对，不自动撤销或伪称按新依据完成。

新操作要求节点仍属于当前用户的有效路径、蓝图版本和该节点状态修订匹配。并发确认与路径编辑冲突时不覆盖对方；用户重读后明确重新确认。重复请求保留同一个提交标识和原始内容，返回原回执，即使节点后来改名／归档；同标识不同内容拒绝。可选成果必须是本账号同一节点已有记录，只在完成时允许关联。归档节点不能新确认，其历史仍可见。

## 顶层实现与验收

复用共享 TypeScript／Zod 领域、Next Server Action、双主题 DOM 控件与 Supabase PostgreSQL。状态确认记录独立存储；数据库负责权限、当前版本、状态修订、幂等和历史上下文。查询以同一语句读取当前路径及状态，最近历史明确限量展示；普通日志不含路径正文、完成依据或成果内容。

Web 提供成长档案内可发现的状态工作台，账号绑定写入；扩展接口采用既有精确 OAuth 身份规则。只读用户权限、匿名拒绝、禁止直接写表及最小权限必须通过实际数据库测试。不扩展管理员密钥权限、不重置数据库。

操作前先保存账号隔离、带格式版本的恢复请求；回执不明时只能原请求重试或重读，不静默重新生成提交。存储不可用时不能发送未持久化请求。切账号隐藏原账号上下文，多标签不同时改写恢复草稿，主题切换不清空内容。服务失败不是空路径或成功。

验证面：真实公共数据库操作、实际 SDK／HTTP／Server Action、公开 React 交互、真实本地 Auth→生产 Web→数据库→页面；双主题桌面与窄屏、离线／重载、并发／归档／另一账号。每个行为先失败再实现。正式 3D、奖励、Agent 状态变更和安装扩展 UI 不在本批交付范围，仍属于完整路线。
