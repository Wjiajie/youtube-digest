## 已确认的原因与处理

1. 关闭自阴影、改为中性非金属灰模后，原减面模型仍有折面，不能归因于单纯的灯光或阴影问题。原文件带法线，其长度接近 1；没有退化三角形或反向的顶点／面法线点积。
2. 同位置拆分顶点的法线不连续确实存在。仅重算法线的 v2 改善了一部分明暗，但无法恢复已经删除的鼻、眼、嘴几何，因此不采用它作为后续主候选。
3. 在真实浏览器载入约 157 MiB 的原始母版后，确认母版本身保留可辨认的五官。问题主要出现在减面后的细节保留与分配，不能据此宣布原始图生模型失败。
4. 普通整身简化的 v3、加入法线误差的 v4 仍无法在合适面数内保住面部。改为对面部区域使用更严格的几何误差，身体使用法线感知简化，两部分切分边界均锁定，再合并索引并压紧顶点缓冲。

v8 的原模型坐标保护区域为：三角形任一顶点满足 `abs(X)<0.10`、`0.55<Y<0.8`、`Z>0.1`。此框仅针对当前人物，不是通用人脸识别。区域几何误差阈值为 0.001，其余部分综合误差阈值为 0.03；这两种误差含义不同，不能直接当作毫米或像素误差。切分边界锁定用于避免简化引入新的接缝错位，不证明原模型没有洞或衣物融合。

采用已安装的 `meshoptimizer 1.1.1`，用本地 Node CLI 保存新文件。API、上传、下载仍遵循 Meshy CLI；本轮没有远程操作。方法依据 [meshoptimizer 官方 JavaScript 文档](https://github.com/zeux/meshoptimizer/blob/master/js/README.md) 的属性感知简化与边界锁定。普通简化和最终格式校验通过 [glTF Transform CLI](https://gltf-transform.dev/cli) 4.5.0 执行，没有修改项目依赖清单或 lockfile。
