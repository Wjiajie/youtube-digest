## 人物门禁与目前能用的母体

本轮从官方 MPFB 2.0.17、MakeHuman CC0 system assets 和 faceunits 生成了 `wuxia-base-mpfb-candidate-v1.blend`。它有 53 根 game-engine 骨骼、52 个 ARKit 名称面部动作单元及可独立处理的眼部资产。另做了 `固定坐姿的技术试摆`，只证明骨架能被摆动，**未**证明衣裙变形、手指握剑或与船座接触。

MPFB 默认脸与 `R07` 不是同一人物。把历史 Meshy 高模面部自动投射到母体的 v2 尝试产生明显破碎表面，因此 v2 也被否决。旧 v17 虽有纹理，发束和肩颈残片仍未通过先前的美术审查。当前没有任何一件人物 GLB 可诚实地标为可上主页的完整角色。

已从母体和两件审查道具构建 `wuxia-scene-blockout-v1.blend`，构建脚本为 `build-scene-blockout.py`。场景含同一 53 骨母体、坐姿试摆、舟剑、座位与右手握点标记，贴图已打包，便于继续在 Blender 中修改。工作台截图可见目前腿、座位、剑与手的相对位置。**这是空间 blockout**：脸、衣、发、接触点和动画均未签收，截图中的无衣母体不进入网页展示。
重新打开 `.blend` 的读回检查发现 11 个对象、1 套 53 骨 armature、舟剑各 1 个网格、11 张打包图像与 2 个定位标记；这只验证文件可继续编辑，不证明姿态接触正确。

### Meshy 失效后的工具复核

已核对本机显示适配器为 AMD Radeon 8060S。微软官方 [TRELLIS 仓库](https://github.com/microsoft/TRELLIS)要求 Linux 与至少 16 GB 的 NVIDIA GPU；腾讯官方 [Hunyuan3D 2.1 依赖](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/requirements.txt)含 CUDA 12 计算组件。这两条不能当作本机即装即用的免费后备。云端 GPU 可另行评估，但也不能保证从单张 R07 自动得到同一脸和可换装拓扑。

Reallusion 的 [CC5 + Headshot 3](https://www.reallusion.com/character-creator/headshot/)提供更有针对性的图生头、形状调节与面部绑定；目前官方列出的组合价格为 **US$329**。但 [Headshot 试用版不允许保存或导出](https://www.reallusion.com/character-creator/headshot/download.html)，[CC5 最低硬件规格](https://faq.reallusion.com/en/Product/Character-Creator/Character_Creator_5)列出 8 GB VRAM，而且[官方内容许可](https://www.reallusion.com/license/content.html)对应用内角色创建系统要求另行询问 Enterprise 条款。因此当前不购买或安装这一路径；若要转向它，应先取得适合机器和网页换装用途的明确许可与预算，再用 R07 做实际头雕验证。

人物下一道制作门禁仍是：在**同一母体**上将脸形、五官间距和肤色对齐 R01／R07；独立建立两套衣装和两套头发，共用同一实际骨架；坐姿四组合逐一检查裙袖、发际线、手指与剑、船座接触；随后才导出动画、制作空闲循环和网页装配清单。骨骼名称相同、四个按钮能点或渲染出一帧都不足以放行。

## 独立审查页

开发环境运行 `npm run dev:web` 后打开 `/design/wuxia`。页面和舟剑文件接口只在 `NODE_ENV=development` 中工作，资产由固定名称、文件路径与 SHA-256 清单校验；无需 Supabase 登录环境。镜头从主视角水平最多 ±8°、俯仰约 ±6°、距离 6.2–8.2；提供键盘可达按钮、重置、文字状态、WebGL 失败提示。页面明确写出人物未过线，剑目前只是放在船上做比例审查，**没有**声称握持绑定。主页代码未接入这些候选资产。

验证证据：

- 新路由、资产守卫及邻近的资源释放／蒙皮加载四个测试文件合并运行：**17 个测试通过**。覆盖固定名称、路径逸出、哈希不符、文件缺失、非开发环境 404，以及原有资源释放和 glTF 蒙皮处理。
- `npm run typecheck -w @blueprint/web`：通过。
- 本地 Next dev + Chrome Headless：桌面 1440px、窄屏 390px 均 HTTP 200、舟剑首帧出现；点击“向左”后实际画面改变；无页面脚本错误、HTTP 错误或横向溢出。审查截图：`桌面`、`窄屏`。这些是**浏览器技术验证**，不是实体设备、性能或人物美术验收。

## 下一阶段顺序

1. **G1 身份头雕**：以 MPFB 母体为可编辑起点，在 Blender 单独调整脸形、眼鼻唇和头皮，对照 R01／R07 的正面与三分之四视角签收；不再用失败的 Meshy 自动投射结果继续叠补。
2. **G2 模块**：制作两套真实衣装网格、两套头发和发饰包，记录骨架版本、bind matrix、头皮与衣缝接口、隐藏身体区域、剑握点和座位基准。导出后读回 GLB，逐件检查 skin、morph、节点、材质与几何；四组合是独立验收对象。
3. **G3 固定坐姿与待机**：为四组合完成同一坐姿、呼吸与眨眼循环，处理裙袖及头发次级运动，确认循环首尾与握剑接触；禁止用图片层或预渲染替代几何。
4. **G4 页面装配与性能**：在 `/design/wuxia` 接入经过 G1–G3 验收的人物 manifest、并发加载与失败回退；桌面真实浏览器跑完整循环和受限镜头四组合，记录下载字节、解码、显存估算与帧时间。
5. **G5 主页接入**：只有人物、组合、舟剑接触和性能全部过线，再把独立展示体验接入主页，同时保留不可用时的 DOM／二维可操作回退。

本轮没有继续提交 Meshy 付费任务；剩余的关键工作是面部与服装／头发的人工可编辑建模、绑定和视觉验收。
