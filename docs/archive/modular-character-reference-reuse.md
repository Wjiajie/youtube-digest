# 武侠模块化角色：逐图复用与最少补充输入

核对日期：2026-09-25。配套 [制作调研](modular-character-production-research.md) 与 [来源及证据](modular-character-research-sources.md)。本轮逐张打开实际文件检查，未生成或修改图片。下文提示词是**未来补图草案，不是已有图片的实际生成记录**；接收清单中的原始提示词和模型仍为未知。

## 1. 先保留什么

主图决定人物气质、色彩和构图；R01/R07 帮助保持身份与服装语言；R02 补背面设计；R03–R06 已覆盖舟、剑、环境；两张 R08 用于坐姿意图。它们不是同一次三维扫描的严格投影，不应强行解释成所有细节一致的工程图。

“直接复用”指继续用于指定的设计／建模／背景环节，**不等于可以不经处理直接变成合格模块**。9 张制作图仍有价值；旧文档中“无需补图”的判断只适用于当时整身静态灰模的输入，不足以覆盖本次可换装、表情和次级运动要求。

## 3. v17 反馈应怎样影响参考使用

用户反馈截图 标出的前垂厚条与肩颈旧残片仍未解决。v17 的新背发只替换第二个 primitive，第一部分保留了旧身体／头发／服饰混合几何。继续给背发加层次不会自然清掉这些区域。

不能按颜色把肩部深色长条一律删除：R01 和 R07 中既有发束，也有装饰带、衣领和饰品。后续先把这些区域标成“头发、衣物、饰品、未知”，在 DCC 按真实几何检查。未知处由用户或角色美术确认；新图补出的被遮挡结构是**新设计**，不是发现了原图的唯一正确答案。

## 4. 最小补充资料：先三维基准，再补信息

不推荐预先承诺“补三张就够”。所缺的是三个信息组；每组可能通过已有三维模型的渲染、人工画线或几张单视角图片完成。

| 信息组 | 何时需要 | 优先取得方式 | 不要误做的事 |
|---|---|---|---|
| 头脸／头皮基准 | A、B 路线都需要；G1 前 | 当前脸与候选母体同镜头对照；中性正面与严格侧面，显露耳廓、发际线、后脑、颈根 | 不让新图擅自换脸；不从表情图片自动推断肌肉拓扑 |
| 无头发遮挡的服装层级 | 实际母体比例选定后，G2 前 | 用母体前／侧／背渲染作底图，拆内衣、外袍／裙、腰带与肩饰；画出开口、层叠、后腰、袖口和坐姿让位 | 不独立生出多套比例不一致的“衣服零件”，再靠整体缩放适配 |
| 干净发流与模块边界 | G3 前 | 同一头部渲染上画发际线、分缝、半挽髻、主束、前发和后发分区；正／侧／背一致 | 不把 R02 的碎波浪当不可更改要求；不让新背发继续与旧前发混用 |

**母体基准由 DCC 生成**：统一 A-pose、单位、身高、关节与镜头，保存正侧背渲染。还没有母体时，可以先用合身灰色连体衣概念草图讨论轮廓，但它不是尺寸、隐藏身体或绑定依据。选择标准母体必须允许目标分发用途；本轮不采购或安装。

剑与舟不列为强制补图项：R03–R05 足够开始代理几何。若原型显示手握不稳，优先截取真实三维握持视图做修正；若用户要拔剑，再补刀身、鞘口和握持转换设计。基础眨眼和呼吸先在中性母体手工制作；只有表情风格尚未确定时，才补少量表情参考。

## 5. 可复制补图提示词草案

使用方式：在图像工具中**实际上传所列原图／三维渲染**，不要只粘贴仓库路径。每次只生成一个指定视角，用同一批身份参考与已认可版本逐步编辑；拼在一张图上的多视图不自动保证一致。下列拟议文件尚不存在，名称只用于未来归档。任何生成仍需后续执行授权，本轮没有提交。

### A. 中性头脸结构参考

输入：主图＋R07＋R01 的原文件。优先用已经选定的头部 DCC 渲染作为第四张锚点。先正面，认可后再单独请求侧面。

```text
为同一位成年东方女剑客制作中性头部建模参考。保持所附主参考的人物身份、脸型、眼鼻唇比例、肤色与气质；R07 用于面部细节，R01 用于整体比例。不要变成另一个人，不增加妆容或新饰品。
本次只输出严格正面的一张头肩图，中性闭口、平视、均匀柔光、浅灰背景。头发临时向后整理，显露双耳、脸侧轮廓、颈根与发际线；肩颈用简洁无纹样衣领覆盖，不让头发或装饰遮挡结构。不添加尺寸数字、文字、拼图或第二个视角。
遮挡处允许作保守的结构设计，但必须与现有身份一致；这是一张供人工确认的设计参考，不是三维扫描或真实比例测量图。
```

侧面续作时将“严格正面”改为“严格左侧面，保持前一张已认可正面图的五官比例与发际线”，同时上传认可正面图。拟议命名：`r10-head-neutral-front-v1.png`、`r10-head-neutral-side-v1.png`。不要求一次同时提供前后左右表情表。

### B. 同一母体上的服装分层

前提：已有选定母体的准确 A-pose 渲染。输入：该视角母体渲染＋R01＋R02＋主图。每次明确一个视角、一个衣层；隐藏层设计需要审查。

```text
以所附三维母体渲染的体型、姿势、肩宽、腰线和四肢位置为固定基准，为同一位武侠女剑客整理服装结构。本次仅制作背面外层衣袍的设计参考。
继承 R01、R02 和主图的象牙白、灰绿、腰带和装饰语言。完全移开头发与可拆饰品，使后领、肩部、背片、腰口、侧缝、开衩和袖根可见；不要改变母体比例，不添加另一套衣服，不把头发画进衣物。清楚区分外袍与露出的内层，避免把所有衣层融合成一张连续皮。
保持均匀光照和干净背景，只输出这一视角。不要绘制未经测量的纸样、尺寸数字、UV 或法线贴图。原参考没有展示的结构作为待确认设计处理。
```

拟议命名：`r11-outfit-outer-back-v1.png`。正面／侧面或内层沿用同一母体另作请求；不需要为每条缝生成图片。裁片、缝合和尺寸在 MD／DCC 中定义。

### C. 干净、顺畅的发型分组

输入：选定头部的单视角 DCC 渲染＋主图＋R07；R02 只参考长度与半挽结构，不继承所有碎波浪。必要时附用户反馈截图指出应避免的问题。

```text
为附图中的同一位成年女剑客设计可制作成游戏发束与发片的长发。本次只输出背面，严格保持所附头部渲染的头型、发际线和发髻位置。
保留半挽发髻与长发的武侠气质；大束顺畅下垂，只有柔和的走向变化。明确少量主束、中层束和稀疏边缘细发，根部有清楚归属，发尾有自然层次。不要厚塑料整壳、面条状密集管束、脏碎三角残片、凌乱波浪堆叠，避免头发与肩饰、领口、腰带粘连。发饰保持独立且简洁。
均匀光照、浅灰背景，完整显示从头顶到发尾。只输出一个视角，不要拼图、文字或假装技术正确的 UV／透明／法线／方向纹理。图片用于确认发流，实际导向曲线、发片和图集由三维工具制作。
```

认可背面后，上传同一版背面图与头部正／侧渲染分别补对应视角。拟议命名：`r12-hair-flow-back-v1.png`，随后才有 `front`、`side`。前发需要单独清理与设计，不继续继承 v17 中未通过的旧网格。

### D. 条件性补充：饰品连接／手握剑

只有原型无法从现有图确定装饰带归属或剑穗连接时才使用；不是必须生成任务。

```text
根据所附 R03 与实际三维手握剑截图，只澄清剑柄、护手、剑鞘口和剑穗连接的结构。保持现有剑的颜色和装饰语言，不改变整剑长度和手的比例。展示一个与截图相同角度的近景，使手指接触位置和穗绳挂点可辨；不要添加额外手指、另一把剑或无法实现的悬浮连接。尺寸由三维工程确定，图片不要编造标尺。
```

## 6. 图片阶段的停止条件

图片可以通过审美确认，但不能替代下面的三维证据：完整身体／头皮、眼睑闭合、服装分层与开衩、同一骨架权重、坐姿无明显穿插、手柄接触和网页材质结果。若连续补图仍只改善表面观感，应回到 DCC 小样，不继续用更多图片推迟结构决定。

参考优先顺序为：用户最新明确反馈 → 已认可的总体身份与设计 → 选定三维母体／模块接口 → 辅助图片。具体装饰冲突保留待确认标记；不得将一张新生成图自动提升为唯一权威。
