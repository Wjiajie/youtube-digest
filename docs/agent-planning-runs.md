## 用户结果与边界

- 用户确认 Goal Brief 后发起一次规划；数据库读取真实定义和当前蓝图，保存来源快照。浏览器不提交 `confirmed`、完整输入或模型规则来替代真实记录。
- 同账号同时最多一个等待／生成中的运行。同一个运行 ID 的精确重试返回原记录；改换定义、修订或日期后复用 ID 会被拒绝。
- 运行可以读取、取消和恢复已完成草案。重新打开不自动再次调用供应商。中断的调用不能证明免费，因此不会自动重跑。
- 草案保存完整节点、周安排、假设、来源修订及 Skill 正文／版本／摘要。来源已变化时标记过期，不把旧建议伪装成当前可确认结果；后续正式提案仍须单独审阅与版本检查。

## 顶层设计

数据库保存运行与账号可用规划次数。新账号默认零次，仅平台管理端可授予；这是次数保护，不是人民币预算或供应商精确账单。开始时预留一次；领取执行权前取消、等待超时或来源修订失效可归还，供应商调用获得执行权后不自动归还。记录真实可用 token，用量未知就保持未知。

Web 身份可开始、读取和取消自己的运行，扩展和匿名均不可访问。本次开始 RPC 只建立记录，不调用模型；只有服务端可领取唯一执行权、登记固定 Skill 与写入结果。执行权不可重领；服务器断线后下一次请求只能恢复状态，不能把曾领取的运行当作尚未消费。

开始／取消／领取／完成均是短事务，先锁用户蓝图再锁运行／额度，网络调用在事务之外。等待记录 120 秒失效，执行记录 120 秒失效；现有生成器自身最多等待 60 秒。五个运行 RPC（包括读取）会落实期限与来源变化带来的状态更新，不自动生成：等待超时变为 cancelled，未领取时来源失效变为 failed，120 秒执行租约到期变为 interrupted；已完成建议来源变化变为 stale，保留原结果。生成器的 60 秒等待截止若成功提交回执，则记录为 failed，结果原因为 timed_out；它与尚无完成回执的租约到期分开表达。两类执行超时都保留已消费次数，不依赖后台队列。

RLS 保护的表 SELECT 只读取已存储的历史快照，不实时推进状态。产品恢复及判断当前运行状态必须使用 `read_path_planning`，不能把直接读到的 ready／running 当作当前新鲜度结论；任何正式写入仍须经过独立提案审阅与来源版本检查。

安全采用明确函数授权、私有写入实现、RLS 和账号条件，不依赖浏览器声明；参考 [Supabase 函数权限](https://supabase.com/docs/guides/database/functions) 与 [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)。服务端密钥不进入共享包、扩展或页面。

## 本批实现契约

- 开始输入：runId、briefId、expectedBriefRevision、expectedBlueprintVersion、startDate；当前 UTC 日期前后一天范围允许时区差。验证当前确认状态、目标容量与截止日期。保存不可变输入，变更来源不能被精确重试覆盖。
- 状态：queued、running、ready、failed、cancelled、interrupted、stale。终态不再执行。取消运行中请求只能禁止接受结果，不能保证供应商停止计费。
- 用户只读结果不包含执行租约。服务端领取必须提交 ownerId 与不可泄露的 leaseId，且只允许 queued→running 一次；同 lease 重试也不重新授予执行权。
- 领取前重新检查已确认来源是否仍然有效。记录中的 Skill 摘要必须与实际执行文件一致，部署换版不能静默更换规则；无法确认是否领取成功时不调用供应商。
- 完成只接受匹配执行权，原样重试幂等；不同完成内容不能覆盖旧回执。取消先发生时丢弃迟到草案，仅保留脱敏状态和用量。ready 结果再次核对 Brief 与蓝图修订；变化时保存为 stale。
- 数据库保护账号、状态、执行权和大体结构；模型草案继续由已有规划器验证。即使已有 ready 运行，本批也不会自动生成或确认正式蓝图提案。
- 仅保存结果时允许一次完全相同的请求重试，以恢复“已提交但响应丢失”；这不是重试模型。持久化始终失败时返回 unavailable，不把只存在进程内的草案作为已恢复结果。
