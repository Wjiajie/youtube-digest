# 对话驱动的角色能力

角色控制以当前加载的模型为准。模型控制器在资源加载完成后生成一份能力快照，包含模型标识、每次加载的唯一版本号，以及可用控制项的类别、标识和名称。模型切换、加载失败或卸载时撤销旧快照；新模型加载成功后发布新的快照。

文字请求携带当前快照；语音连接在认证时携带快照，运行期间切换模型则更新语音会话的工具目录。服务端根据快照生成 `avatar_control` 的工具定义，未加载模型或没有能力时不提供该工具。控制器、对话运行时和服务端分别校验控制项、参数和版本号，旧对话轮次或旧模型的指令不会应用到当前模型。工具结果表示指令已排队，实际效果仍以本地模型的执行为准。

目前协议支持表情、动作、服装、头发和原始形变：动作不需要数值；服装是开关；其他数值为 0–1，表情和形变可指定持续时间。只有确实可用的项目进入目录，当前快照最多包含 256 项，超出的项目不会公布；目录中的模型元数据当作数据处理，不授予执行脚本或任意骨骼操作的能力。语音口型由语音播放控制，角色适配器需避免与其冲突。自动选择服装或头发需要用户明确提出；Agent 的外观控制是当前场景中的临时状态，不写入用户保存的外观偏好。

## 接入其他模型

通用契约和校验位于 `avatar-capabilities.ts`，模型侧由控制器实现 `getAgentCapabilities()` 和 `applyAgentControl()`。新模型的适配器应检查加载结果，只公布模型真实支持、可以解释的控制项；将协议中的标识映射到该模型的表达式、动作或外观实现，并处理其生命周期与视觉冲突。新类别或不同参数范围需先扩展共享契约、工具定义和两侧校验，并增加相应测试。当前内置适配器针对 Shayna 的资源和目录；并不意味着任意 VRM 都已自动支持服装、发型或动作。

## 验证边界

自动化测试覆盖不同能力目录、无能力、非法参数、旧版本与旧轮次，以及文字、语音工具目录的传递和更新。模拟供应商无法证明真实服务一定会按意图选择工具，也无法证明供应商在进行中的语音会话接受工具目录更新；这些行为需要在配置真实服务的环境下另行验证。
