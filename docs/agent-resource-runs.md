# 资源运行记录与显式恢复

更新：2026-09-10；固定点 `fc825f7`。P4/P6/P7 本地服务端增量：真实账号、数据库、供应商适配器和模型 SDK 已接通。外部响应使用本地 HTTP 夹具；尚无正式页面、生产 worker 或托管启用，不代表真实推荐服务已经可用。

## 用户结果与边界

资源推荐不再依赖一段随页面消失的内存执行。首次检索、读取字幕任务、内容匹配分别保存输入、执行权和结果；重新读取或重复提交同一个请求不会重新消费。所有输入来自当前账号的正式路径或其服务器保存的上一份结果，不接受客户端提交的视频、字幕任务 ID 或“推荐证据”。

三种操作独立启动、独立计次，不自动推进：

| 操作 | 使用的依据 | 一次执行的上限 |
| --- | --- | --- |
| 检索 | 数据库当前学习类型 Path Node、用户偏好与学习背景 | 一次搜索、一次详情、三次原生字幕请求 |
| 字幕继续 | 上一份已保存结果中的待完成任务 | 最多三次已有任务读取，不重新检索、不启动转录 |
| 匹配 | 已完成字幕检查、至少一份可用证据的结果 | 一次受控模型生成，不自动重试 |

字幕任务仍处理中时，保存这一事实；以后可再明确发起一次继续操作。匹配前必须处理完所有待完成任务，避免把尚未检查的候选悄悄当作不合格。没有合格视频、无字幕、语言不适合和供应商错误不会被包装成成功推荐。

每个结果最多接一个后续操作，取消后的后继也保留。这使一条执行链不会因重复点击分叉消费。相同请求 ID 只能恢复原操作，不能更换参数或任务来源；已取消或中断的链若需重新检索，必须明确发起新链，不能把重新消费伪装成免费重试。未来界面必须清楚说明这一限制。

## 数据、额度与失效

新增[增量迁移](../supabase/migrations/20260910095541_resource_runs.sql)，保留原账号和业务数据。账号只能读取自己的记录，不能直接修改；匿名账号、其他账号和扩展 OAuth 不能使用这些 Web 规划操作。私有额度与租约不向客户端开放。

检索、字幕继续、匹配各有独立可用次数，默认均为零。开始时预留一次；尚未获得执行权就取消、过期或来源失效时退回一次。取得执行权后，即使网络响应丢失或调用失败，也不自动退回——供应商可能已经处理并计费。次数不是人民币账本，也不承诺提供方免费额度。

排队和执行记录各有 120 秒期限。读取记录会处理过期和来源失效，但不会启动供应商请求。失去执行权回执时不猜测是否成功，不调用供应商；完成结果已保存但响应丢失时，只允许原封不动地再提交一次保存回执，不重新执行。

记录绑定蓝图、版本和具体节点。执行前蓝图发生改变会拒绝旧预留；执行中或完成后改变蓝图，成功结果保留为过期历史，不能冒充当前建议。匹配依旧只是待审阅建议，不写正式 Resource Binding 或修改路径。

候选与字幕有严格结构和体积限制；两条视频不能共享一个待完成字幕任务。继续任务时保留原视频信息和已有字幕，只更新原待完成任务对应的结果；返回另一个任务 ID 会被拒绝。Skill 正文及校验值保存在匹配记录中，供应商错误、密钥与取消原因不进入普通结果。

## 实现与验证

- [云端编排](../apps/web/src/lib/agent/cloud-resource-runner.ts)把持久执行与现有检索／匹配连接起来；[只读恢复与取消](../apps/web/src/lib/agent/resource-run-access.ts)无需模型或 worker 凭据。
- [字幕继续](../apps/web/src/lib/resources/caption-resume.ts)只有一次有界读取，不轮询或自动转录。
- [真实账号联调](../apps/web/agent-integration/resource-runs.spec.ts)走本地 Supabase Auth／PostgreSQL、实际 YouTube／Supadata 适配器和官方 DeepSeek SDK；只有第三方 HTTP 响应被本地夹具替代。
- [数据库回归](../supabase/tests/resource_runs.test.sql)检查公共 RPC、RLS、分项额度、单次执行权、任务来源、幂等回执、取消／过期／失效和删除级联；[升级契约](../scripts/test-m1-migration.mjs)逐行核对已有数据保持不变。

测试没有给真实用户增加额度，没有重置数据库、调用付费 API、变更托管项目或发布客户端。SQL 只做来源／执行保护及有限结果校验；完整结构和字幕引用验证仍由实际 Node 运行器负责，不宣称数据库能证明语义正确。
