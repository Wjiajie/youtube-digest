# 用户主动发起规划

固定点 `f280c0d`。本批接通已确认定义 → 用户主动生成 → 持久运行 → 已有阅读与提案确认；不启用托管模型，不进行付费推理。

## 执行契约

- 目标定义的规划页显示起始日期与生成入口。只有平台显式启用且服务端模型／工作客户端配置齐全才开放；定义未确认不可发起。没有配置时明确提示，不以测试模型返回成功。
- 每次主动请求携带账号、固定运行 ID、定义修订与蓝图版本。只接受同源 Cookie Web 请求，鉴权、账号匹配与严格输入检查后才进入既有运行器；数据库检查真实来源、次数和唯一执行权。不得从客户端选择模型、密钥、数据库地址、Skill 或草案。
- 使用官方 `@ai-sdk/deepseek` 与 `deepseek-v4-flash`，直连官方端点；不隐式切 Gateway，不自动重试供应商。真实供应商费用需单独启用与受控额度，默认关闭，新账号默认零次。
- 生成请求可独立于 Server Actions 运行，以便另开运行页核对及取消。请求等待期间和响应不确定时提供同一运行地址，不自动重复生成；页面刷新只读历史。生成结果不是正式路径，不自动应用或标记学习完成。
- Vercel Node 只执行推理，用用户访问令牌和独立随机服务凭据调用固定的 `planning-worker` Edge 函数。Edge 自行验证 JWT 签名／有效期与真实用户，拒绝匿名和 OAuth 扩展身份，从已验证身份取得 owner；仅允许领取执行权和保存结果。管理员密钥只在 Edge，不进入 Web、扩展或 Vercel；不提供任意 RPC／所有者参数或正式提案写入通道。
- 独立服务凭据至少 32 字符，不能使用 Supabase 管理员密钥代替。现有已签发 JWT 的撤销仍受访问令牌有效期约束，不宣称即时注销失效。版本化 Skill 必须随生产服务端文件追踪打包；不进入静态客户端或扩展包。
- Edge 请求体限制为 8 MiB；领取执行权前检查捕获的既有蓝图 JSON（UTF-8）不超过 1 MiB，为新候选、JSON 转义、依赖、Skill 与元信息预留至少 7 MiB。当前最多 128 节点的字段上界可容纳其中。超限时不调用模型，取消尚未领取的运行并退回次数；若取消响应不确定，只报告恢复状态，不声称已退款。后续扩大字段或节点数量必须重新验证传输预算。
- 临时 Auth 故障与限流返回不可用，不伪装成退出登录；只有已知身份拒绝才隐藏私人内容。生成页的新标签入口保留原请求，不承诺用户主动关闭原页后继续后台运行。

## 验证范围

以公开 HTTP 请求、真实本地 Auth／数据库及 DeepSeek SDK 的外部网络 seam 测试。第三方响应仅在测试进程注入，不添加生产测试开关或自定义代理地址。校验同源、身份、输入、关闭状态、零额度、一次执行和结构化结果；组件验证显式点击、未知结果与账号变化；生产构建核实 Skill 文件追踪。离线响应不证明真实模型质量、人民币账务或完整 P6 通过。

资料依据：[DeepSeek 首次调用](https://api-docs.deepseek.com/)、[AI SDK DeepSeek 适配](https://ai-sdk.dev/providers/ai-sdk-providers/deepseek)。2026-09-10 已核对当前 Flash 名称与固定安装版本；此文不承诺价格不变。

## 本地证据

- `check:m1`：443 项 Vitest、26 项 Edge 处理器测试、四工作区类型检查、现有账号迁移契约、向导、Web／扩展构建与安全检查通过。Edge 处理器另通过独立严格类型检查。`test:agent-runs` 17 项真实 Auth／数据库集成通过，其中有效但超过 1 MiB 的旧蓝图在推理前停止、退回预留次数，原内容保留。
- `test:planning-generation`：真实本地账号 → 生产 Next 页面 → 同源 POST → 实际 Supabase Edge 验证双凭据 → 数据库执行权 → 真实 DeepSeek SDK → Edge 保存运行 → 用户审阅确认通过。两条旅程分别验证空蓝图及含 70 个既有节点、超过原 256 KiB 限制的有效蓝图；后者保留全部旧完成依据并成功确认到 v2。
- 实际 HTTP 验证缺少独立凭据、篡改真实 JWT、跨用户运行、任意 owner／操作和超过 8 MiB 正文均被拒绝；生成等待期间打开新标签，原页保持且请求成功完成。另覆盖跨站、坏 JSON、零额度、精确恢复、双主题 320 px、退出身份后隐藏私人历史。2 条既有规划阅读／确认旅程（含默认关闭返回 503）和 36 项普通生产浏览器回归通过。
- 唯一外部替代是测试进程的 `NODE_OPTIONS --import` 网络夹具；严格要求本地 Supabase 与虚构模型密钥，仅拦截官方 DeepSeek 路径。不导入应用、不提供生产自定义模型代理或测试开关，不模拟 Auth 或数据库。
- 实际 `.next` 路由追踪包含 Skill，字节与源码一致；Web 静态文件及扩展构建不包含工作密钥变量、测试密钥或 Skill 正文。生产请求成功也实际执行了 Skill 文件读取，不只检查 manifest。
- 曾复现同源误拒绝：Next 的请求 URL 主机是内部 `localhost`，HTTP Host 则是浏览器地址。以真实 Host 和请求协议核对 Origin 后，原测试通过；不信任任意 forwarded-host，临时探针已移除。新组件另覆盖生成期间核对入口及身份变化后整页私有历史隐藏。
- 复核纠正了初稿的权限设计：管理员客户端已经从 Node 移到受限 Edge，未以改写已批准架构规避问题。Edge 故障分类测试覆盖 Auth 429／503／未知异常，不将其误报为身份丢失。运行测试期间还加强了新启动进程的就绪检查与有界请求体消费，最终真实超限测试返回 413。大页面构建旅程出现过 Next 的 Gzip 监听器警告，未据此声称平台压力／性能验收通过。

配置只记录在 `.env.example`：`BLUEPRINT_PLANNING_ENABLED=false`，`DEEPSEEK_API_KEY` 与 `BLUEPRINT_PLANNING_WORKER_SECRET` 留空。独立凭据仅在 Web 服务端和 Edge 之间共享，不能赋予 Vercel 数据库管理员能力。没有变更实际配置、充值、授予真实用户次数或托管工作密钥。未来开启前仍需审核费用额度、实际供应商质量、平台超时和日志采集；已有次数上限不是人民币账务。
