# 明确读取当前播放位置

更新：2026-09-10；固定点 `2e0966c`。P8 的本地实现增量；不改变笔记云端领域或数据库结构。

## 用户体验

扩展的“记录 → 记录视频笔记”在明确选定关联视频后，提供“读取当前播放位置”。它读取当前活动标签页中同一视频的秒数，向下取整，零秒有效。位置只填入草稿，仍需要用户点击保存。Web 表单保留手动填写，不尝试跨浏览器控制播放器。

读取期间暂时冻结编辑，避免将延迟结果填入另一个来源或覆盖用户的新输入；账号切换会丢弃旧结果。广告、加载、页面切换、播放器不可用或读取超时，都保留已有原文和手动位置。响应未确认的笔记提交不能重新读取位置改变原请求。

不自动轮询、不播放或跳转视频、不记录观看比例，也不据此判定理解或掌握。跨设备继续学习和自动位置同步仍未实现。

## 页面与扩展的职责

后台只接受扩展自己侧边栏的读取请求，核对账号及读取前后的活动标签页；三秒内没有可信结果则失败，不自动重试。只向顶部页面发送公开视频标识，不发送账号、令牌、笔记、节点或蓝图。

两个限定于 YouTube 的静态页面脚本分别负责：隔离环境中的扩展消息及原生媒体检查；页面主环境中的最小播放器读取。主环境入口只识别固定的读取事件和随机关联标识，不接收代码、地址或任意方法名称，不调用扩展账号或云端接口。所有页面返回值都视为不可信数据，核对视频、时间范围、原生媒体时间／时长、就绪状态与广告状态后才用于草稿。

保留现有扩展权限，不增加 `scripting`、`activeTab` 或远程代码。静态脚本、隔离环境及消息机制参考 [WXT 内容脚本](https://wxt.dev/guide/essentials/content-scripts)与 [Chrome 消息传递](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)。

## 为什么不能只看地址栏

单页导航可能先更新页面地址，播放器仍保留旧内容。公开、未登录的实际 YouTube 页面检查还发现：播放器没有预想的 `data-video-id`，标题链接也可能没有地址。因此未采用只在人工夹具里存在的身份属性；实际播放器身份与原生媒体状态要一起核验。

YouTube 观看页的播放器对象和 DOM 并非对第三方保证稳定的接口。缺失或变化时回退到手动填写，不能把一次兼容性样本写成所有视频、广告形态或账号环境均已验收。
