# 提案确认后的资源顺序一致性

更新：2026-09-10；固定点 `bc08cef`。本地修复手工提案、规划提案与资源采用共用写入器的顺序缺陷，不改变产品操作方式，也未托管发布。

## 行为与边界

用户明确确认的节点资源数组就是正式展示顺序。此前通用写入器把所有资源位置存为零，导致正式路径按资源 ID 重排、与已审阅提案及历史修订不一致。现在所有提案类型在同一写入核心中保存数组顺序，Web 与扩展读取一致，不再需要资源采用专属的排序后处理。

- 调整顺序保留绑定 ID；移除只归档旧绑定，已有学习会话仍指向原视频与节点。
- 未产生会话的绑定可以按既有规则移动节点；已关联会话的绑定跨节点移动仍整体拒绝，不能改写历史归属。
- 用户、版本、来源、有效期和不可变提案的保护保持不变。失败确认不留下部分归档或排序结果。
- 原样重放历史确认返回原应用版本，不恢复旧顺序，也不改写历史修订。
- 迁移只修复未来确认的写入行为，不回填现有位置。旧记录保持原样；下一次明确确认的新提案才保存其审阅顺序。

没有新增专门拖动排序／移除界面，不接受调用者自行传入资源 `position`，不新增公共写入接口。
