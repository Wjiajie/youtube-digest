# 首页与正式路径阅读体验

状态：本地实现并验证，尚未上线。批次基点 `e6cddd1`，实现 `5dbe5ca`。对应 P5；不是正式 3D 美术或性能验收。

## 产品边界

首页 `/` 回答当前关注哪个目标、下一步做什么、最近记录了什么。最多展示现有顺序的五个目标，用户可临时选择焦点；不新建持久化偏好。`/paths` 展示全部正式目标，`/paths/[goalId]?node=<id>` 展示完整路径与指定节点。`/goals` 仍是规划前的目标定义，不冒充正式路径。

原有提案编辑器保留在 `/blueprint/edit`，草稿恢复、版本保护、用户确认不变。学习、实践、检查点、复盘均是有效节点，视频是可选资源。所有状态修改仍在明确确认界面进行。

## 阅读模型

通过现有 `read_node_status_workspace` 在同一数据库语句读取正式蓝图和当前节点状态。近期成果读取失败单独提示，不伪装为空记录。前端只接收当前已验证账号的数据；没有新的 SQL、授权或写入接口。

领域公开入口 `projectBlueprintProgress(snapshot, current)` 返回有序 `GoalProgressView[]`。每项包含 `goal`、`nodes`、`next`、`confirmedCheckpoints`、`needsReviewCount`、`awaitingPlan`、`allSelfConfirmed`。节点视图包含 `node`、`stageId`、`stageTitle`、`status`（记录或 null）、`completion`（open/self_confirmed/needs_review）、`blockedBy`（未自确认前置节点 ID）。顺序为 position 后按 ID 确定性排序，不修改输入。

只采用同一蓝图、目标和当前节点的最新 revision 记录。完成记录的节点名称、类型或完成标准与当前节点不同即待复核；仅改变预计时长或重排阶段不使自确认失效。待复核记录优先提示，其次是前置条件满足的进行中节点，再是第一个前置条件满足的未完成节点。前置条件按当前仍有效的自确认计算。待复核提示不是建议绕过前置条件，完整路径始终显示前置关系。

全部节点自确认只意味着用户自评，不称为掌握或目标达成。空路径提示等待规划，不伪造行动或百分比。检查点数字只计当前有效的自确认检查点。历史成果保留当时标题与路径版本；只有节点仍属于当前目标时才链接到当前路径，否则标记历史记录。

## 表现与验收

双主题共享语义和 DOM 操作，表现由已有语义 Token 与主题选择器控制。首页提供身份视觉区域和目标模块，但不把静态身份图形或二维回退声明为最终 3D。窄屏、键盘、减少动效必须可用，主题变化不重置临时焦点。
