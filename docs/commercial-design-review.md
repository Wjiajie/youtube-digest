# Blueprint 商用品质与多主题设计复审

最后更新：2026-09-06。状态：Q1–Q10 顶层方向已收敛；资产与画面可行性待验证，功能尚未实现。

本文记录设计依据、已确认选择、推导方案与待验证事项；阶段状态仍由 [执行路线](execution-roadmap.md) 唯一维护。用户先确认 Q1–Q7 默认项，随后明确 Q8 优先寻找优质开源资产、暂不商业购买，Q9/Q10 按默认项确认。当前代码判断基于工作区源码、现有文档和本会话已验证的历史结果；本轮只补充公开资产资料核查，没有重新检查线上部署或登录状态。

## 已确认的设计方向

- 产品仍是 Agent 辅助的个人目标系统。3D 人物映射用户自身，蓝图连接目标、路径与学习；YouTube 是当前学习资源来源。
- 3D 首页需要具有吸引访问、建立归属感和支持持续维护的设计完成度。
- 多主题从设计之初纳入架构，覆盖 Web 与扩展的相关界面，不再采用“先围绕一套主题实现，以后再考虑扩展”的前提。
- 以可商用产品的质量标准设计与验收。分阶段交付继续成立，但工程验证页面不能自动成为对外产品界面。
- 商业首发交付赛博朋克与东方山水/武侠两套完整主题，覆盖相同核心旅程，不把换色或半成品计为第二套。
- 主题可以改变角色、场景、材质、排版、面板形态、动效与有限构图；目标语义、证据含义、用户确认和导航结果保持一致。
- 登录前提供可跳过的公开示例蓝图；登录后创建和保存个人蓝图，已有用户直接回到自己的主页。
- 维护动力来自目标重点、真实成果与下一步，装饰为补充；同一身份、目标和成果在主题切换后延续，化身可以不同。
- 美术采用精品风格化方向，优先寻找允许目标用途、可改造的优质开源/开放许可资产，暂不商业购买；统一美术指导和商用品质要求不变。当前不因暂缺付费美术预算而停止免费资产选型，也不把免费等同于无需整理、改造或优化。
- 首发每主题一个精修基础形象，加少量配色/配饰预设；更多形态、捏脸与完整换装后续扩展。
- 最小成果记录默认私人文字与作品链接，由用户明确确认；主动分享卡片后续交付，不在最小切片引入图片托管、公开个人主页或社交动态。
- 关键取舍见 [ADR-0003](adr/0003-multi-theme-product-design.md)。上述均为目标设计，尚未实现。

## 已确认的产品表达

### 首页承担三个不同的结果

1. 初次访问：通过可交互且可跳过的公开示例蓝图，让用户看懂这是什么、为何与自己有关，并感受到角色和目标世界的完成度。示例始终注明来源，不暴露真实用户内容，不暗示已经为访客生成个性化路径。
2. 日常返回：清楚显示当前重点、下一步和最近真实进展；角色、场景与成果呈现回应这些内容。
3. 主动维护：整理目标优先级、留下成果、回顾与修订方向，并有可见的个人积累。装饰选择可以带来愉悦，不能自行算作目标进步。

保留人物中心的状态面板定位，以精品风格化角色、材质、灯光、构图、空间关系与克制的动效形成品质，不扩张成可自由移动的游戏。

### 全产品的主题体验

每套主题应明确角色与环境、排版、图形、面板形态、图标、动效节奏，以及路径、Agent、学习、成果和设置等界面的应用规则。状态表达保持一致含义，但色值可以由各主题决定，并满足阅读与辨识要求。

建议 Web 用完整的空间表现承载身份；扩展使用同主题的紧凑、低干扰版本，把主要空间留给视频理解与记录。扩展中的目标上下文、返回路径、保存结果和错误恢复必须保持清楚。

## 推导出的目标架构边界

以下根据已确认选择划分逻辑职责，不代表已实现、立即新增同等数量的软件包或最终接口协议。具体组件与主题装配建议见 [目标 UI/UX 规划](target-ui-ux-plan.md#9-视觉与多主题架构)。

| 模块 | 负责什么 | 需要隔离的变化 |
| --- | --- | --- |
| 目标与学习领域 | 目标、阶段、节点、资源、证据和已确认的结果 | 主题变化不修改这些事实或用户确认规则 |
| 首页展示模型 | 将领域事实整理为当前重点、下一步、可展示成果和身份摘要 | 编辑器结构、关系表和图形渲染不相互依赖 |
| 身份与外观偏好 | 同一用户的主题选择、各主题化身与外观偏好，成果归属不随化身改变 | 视觉选择不触发目标路径修订；账号偏好与设备画质偏好分离；不要求跨主题共用模型和服装 |
| 主题表现模块 | Token、控件视觉变体、有限布局规则、场景和动效资源 | 新主题不复制登录、授权、保存、提案或学习业务逻辑 |
| Web 场景渲染模块 | 资源加载、角色与场景组合、镜头、交互反馈和质量档位 | 高低画质是同一主题的不同表现；资源失败仍保留 DOM 操作 |
| Web 与扩展界面 | 各自的用户任务与信息密度 | 共享语义与基础控件；扩展不必加载 Web 的 3D 资源 |

现有 Next.js、React、TypeScript、WXT 与 Supabase 可以继续作为底座。既有路线中的 Three.js、React Three Fiber、Drei、Blender/glTF 是待验证的 3D 实现候选；选用它们本身不构成美术或产品品质证明。本轮不承诺库的新版本、资产供应商或最终软件包划分。

主题扩展验收实际覆盖两套差异明显的表达：同一条蓝图可以切换表现，当前节点、未保存输入、学习上下文和成果归属保持一致；增加另一主题无需复制业务流程。两套均达到完整对外标准才满足双主题首发门槛，允许内部逐套推进，但不把内部验证称为商业交付。

## 商用品质验收框架

| 门槛 | 可检查的结果 |
| --- | --- |
| 美术完整性 | 人物、环境、字体、图标、面板与动效遵守同一主题规范；对外交付不残留几何体占位或内部阶段说明 |
| 核心旅程完整 | 登录、首页、目标路径、提案审阅、扩展学习与成果返回形成连贯体验；完整未实现功能保持明确状态 |
| 状态完整 | 空目标、长中文标题、多目标、加载、无资源、失败、离线、限额与权限失效都有对应设计和恢复路径 |
| 跨主题正确性 | 切换不丢草案、不改变证据、不重新学习关键操作；一套主题的修复可在另一套复验 |
| 性能与可访问性 | 制作正式资产前先选参考设备与网络、设首屏和交互预算；两主题都测真实资源，并验证低画质、静态回退、键盘和减少动态效果 |
| 真实进展反馈 | 主页变化能解释对应的用户成果；观看时长和装饰操作不能被表达为已经掌握 |
| 生产可靠性 | 托管登录、扩展授权、保存、同步与恢复通过验收；不将邮件请求受理等同于发送或投递成功 |
| 商用资源与运营准备 | 资产、字体来源与许可可追溯；外部用户进入前确认服务费用、SMTP、额度和恢复方案适配实际用途 |

这里的发布质量门槛，与此前暂不设定的留存率或市场成功淘汰门槛是不同问题。质量可以先明确，产品吸引力和维护兴趣仍需用真实使用观察验证，不能由视觉审阅直接证明。

## 路线调整

## 开放资产的落地约束

- 免费下载只是价格信息；先核对具体资产的许可、作者与来源，再确认是否适合修改、商用及随 Web/扩展分发。优先 CC0，符合署名等条件的 CC BY 也可作为候选。CC0 允许商业用途的复制、修改和分发，但不消除商标、肖像等其他权利问题；CC BY 还要求适当署名、许可链接与修改说明。[CC0 官方说明](https://creativecommons.org/publicdomain/zero/1.0/)、[CC BY 官方说明](https://creativecommons.org/licenses/by/4.0/)
- 这是一套项目选型规则，不是对任何素材的法律合规保证。来历不明的游戏提取资源、没有资产许可说明的仓库、仅供非商业用途的资源不进入当前商用候选；软件开源许可不能自动覆盖仓库中的模型、字体和贴图。
- 按人物、环境道具、材质、灯光、动画、图标/字体分开核对；有模型不等于有合适骨骼、待机动作或可编辑源文件，也不等于两主题都达到完整画面标准。
- 建立来源、作者、原始许可、版本、修改和署名台账；最终选择记录到主题资产清单，而不是散落在页面代码里。当前只做资料筛选，不下载或接入资源。
- 免费资源仍需要统一比例、轮廓、材质、光照和动效。若现有资产无法达到双主题品质门槛，先列出缺口和改造成本，再询问是否调整范围；不自动购买、删除第二主题或降低到占位演示标准。

第一轮候选与核查范围见[开放资产研究](open-asset-research.md)，候选不等于正式采用。

## 复审结论与下一步

顶层产品范围已形成一致理解，不再为已回答项重复提问。方向在架构上可落地：保留云端领域底座，分离主题与事实，以两套完整表现检验扩展性，并通过真实成果反馈支撑维护动机。

尚不能承诺的，是仅靠现成开放资产就能达到两套精品画面的制作成本与效果。接下来依据候选清单完成风格板、同一旅程的关键页面和代表性角色/场景验证；确认参考设备、网络、资源与交互预算。只有实际出现无法兼顾品质、双主题范围和不采购约束的冲突，才需要新的产品取舍。资产与性能验收尚未完成，不把设计共识当成上线证明。
