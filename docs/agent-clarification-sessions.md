# 目标澄清：云端会话与回合

固定点：`8883313`。本批连接[澄清引擎](agent-goal-clarification.md)与真实本地 Supabase，交付可恢复的云端编排，不代表聊天页面、托管发布或真实模型质量已经验收。

## 产品与数据边界

- 会话保存一份独立的工作摘要及其来源 Goal Brief 修订。Agent 可以建议修改工作摘要，但不会自动保存或确认 Goal Brief，更不会修改正式蓝图。
- 用户可明确编辑工作摘要、存为草稿检查点，或确认目标定义。保存原子关闭本次会话；仍需后续明确进入规划和提案确认，才可能形成正式路径。
- 回合记录本次实际问题、用户回答、已有问答、来源、Skill 版本与哈希、受控结果和用量。刷新或响应丢失后可以按固定 ID 读回，不要求再次消费模型。
- 只有成功回合进入后续问答历史，问题与实际回答配对。最多带入 12 对历史问答；第 13 个回合完成后，下一次生成明确返回窗口已满。用户可主动保存草稿并从新修订继续，旧记录保留，不静默裁剪历史。相应页面引导待下一批实现。
- 暂停、继续追问和待审阅保持不同状态。暂停不冒充定义已完成；无需模型批准，用户也可以自己补全并明确确认。

## 顶层实现

Node 负责固定 Skill 与 DeepSeek SDK 推理；Supabase Edge 仅提供领取执行权、保存受控结果两项特权操作。Web 不持有管理员密钥。用户会话和明确保存走已有身份验证与用户级 RPC。

- PostgreSQL 是会话与回合的事实来源。公开表只有本人读取权限，无客户端直接写入；匿名用户和扩展 OAuth 身份不能调用 Web 澄清操作。私有租约、次数与精确回执不进入客户端记录。
- 同一账号同时只执行一个澄清回合。独立次数默认零，先预留再领取；排队取消、过期或来源失效可归还次数，已领取且供应商可能运行的失败不假定免费。相同请求与完成重放不重复扣退，不改变既有规划额度。
- 来源被修改、用户取消或执行过期后，迟到结果不能覆盖当前工作摘要。进行中回合阻止同一会话直接编辑与保存；保存同时核验来源与会话修订。
- Edge 校验独立工作密钥及真实用户 JWT，服务端推导账号，不接受客户端指定 owner 或任意 RPC。两类 worker 共用身份、错误脱敏和请求体读取规则，保留各自操作与结果校验。
- 澄清请求最多接受 1 MiB、原规划仍为 8 MiB。超限后不保留额外内容，消费上传至结束后返回 413；整个读流过程有 5 秒期限，停滞上传返回 408，取消流本身不延长期限。极慢客户端的代理传输表现不等同于本地处理器返回时间。
- `BLUEPRINT_CLARIFICATION_ENABLED` 默认关闭，另需独立 `BLUEPRINT_CLARIFICATION_WORKER_SECRET`。本批仅准备服务端配置与模块，尚无用户可触发的澄清生成路由；不能把配置存在视作已上线。

## 本地验证

- 新增迁移前后，已有账号的全部 public/private 数据逐表一致，包括运行中的规划记录、租约与 Skill；未伪造历史或赠送真实账号额度。
- 真实本地数据库 525 项 pgTAP／12 文件通过，其中澄清 100 项；独立非作者复核通过。源码与本地迁移历史 12 项对齐；托管仍为旧 7 项，未修改。
- 真实本地 Auth／数据库／AI SDK 共 23 条集成回归通过，含 6 条澄清旅程：独立摘要与明确保存、两轮问答与重放、并发取消、零额度与跨账号拒绝、来源变化、分页读取。
- 真实 Edge HTTP 的生成—恢复—明确草稿保存、伪造身份／owner 注入／跨账号拒绝、连续请求后的超限处理，3 条测试通过。仅替换外部模型网络响应，不替换应用编排、Auth 或数据库。
- 其中模拟“Edge 已保存成功，但 Node 没收到完成响应”，精确完成重试读回原结果，模型仅调用一次；不存在为恢复页面而自动重新推理。
- 排查超限请求时，独立大请求通过而连续请求后超时。单纯不等待取消和读取前序响应都无法稳定修复；改为限内保留、超限消费、总时限控制后完整场景通过。新增停滞且取消永不结束的流测试，先失败再通过。
- 完整 `check:m1` 通过：475 项 Vitest／46 文件、41 项两类 Edge 处理器测试、四工作区类型检查、既有账号迁移契约、向导、Web 与扩展构建和安全检查。新增集成测试及两类 Edge 测试另通过严格类型检查。
- 原规划的空蓝图与 70 节点大蓝图，在真实本地 Auth、生产 Web、Edge 与数据库间完成生成、阅读、明确确认，两条浏览器回归通过。大页面仍出现之前已记录的 Gzip 监听器警告，不将功能通过当作性能问题已解决。
